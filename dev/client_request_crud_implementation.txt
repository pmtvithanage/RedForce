DATABASE CONSIDERATION - IMPORTANT!
=================================================================

Your database table has TWO different column naming conventions:

OPTION A (in sql.sql):
   - guard_type (ENUM: 'Armed', 'Regular')
   - guard_count (INT)

OPTION B (in your code):
   - number_of_guards (INT)

CURRENT IMPLEMENTATION:
The code I created handles BOTH scenarios by checking for both column
names:

In v_client_requests.php:
<?php echo $request->number_of_guards ?? $request->guard_count ?? 'N/A'; ?>

This ensures it works regardless of which column name exists.

RECOMMENDED ACTION:
Check your actual database table structure:

1. Run this query in phpMyAdmin or MySQL:
   DESCRIBE service_requests;

2. If you have 'guard_count', you may want to run:
   ALTER TABLE service_requests 
   CHANGE COLUMN guard_count number_of_guards INT NOT NULL;

3. If you have 'guard_type' but it's not being used, you can drop it:
   ALTER TABLE service_requests 
   DROP COLUMN guard_type;

The current M_client.php model uses 'number_of_guards', so that's
the recommended column name.

HOW IT WORKS:
=================================================================

CLIENT SIDE:
1. Client submits service request form (v_requests.php)
2. Request saved to database with status = 'Pending'
3. Client can view history and see status (Pending/Approved/Rejected)

ADMIN SIDE:
1. Admin clicks "Client Requests" stat card in Clients page
2. Redirected to admin/clientRequests
3. See all requests with color-coded status badges
4. For Pending requests, admin can:
   - Click "Approve" button → status changes to "Approved"
   - Click "Reject" button → status changes to "Rejected"
5. Status updates immediately reflect in client's view

STATUS FLOW:
Pending → Approved (green badge)
Pending → Rejected (red badge)

=================================================================
TROUBLESHOOTING:
=================================================================

If you encounter issues:

1. "Column not found" error:
   - Check database column names (number_of_guards vs guard_count)
   - Run DESCRIBE service_requests; to verify

2. Requests not showing:
   - Verify data exists: SELECT * FROM service_requests;
   - Check foreign key: SELECT * FROM users WHERE role = 'client';

3. Status not updating:
   - Clear browser cache
   - Check flash messages for error
   - Verify database permissions

4. Styling issues:
   - Clear browser cache
   - Verify CSS file path is correct
   - Check browser console for 404 errors
