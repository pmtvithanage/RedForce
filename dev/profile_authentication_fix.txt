PROBLEM IDENTIFIED:
When you copy-pasted the client profile code to other roles (supervisor,
premise officer, mobile rider), the profile views were still including
the CLIENT sidebar (v_client_sidebar.php) and CLIENT CSS. This caused
authentication issues because:

1. The client sidebar checks for 'client' role
2. When a supervisor/officer clicks another menu item, the client 
   sidebar kicks them out because they don't have 'client' role
3. The CSS was also pointing to client folder instead of their own

ROOT CAUSE SUMMARY:
=================================================================

The issue was simple: Copy-pasting the client profile HTML to other
roles kept the client sidebar reference. When supervisors/officers
loaded their profile, the client sidebar authenticated them as
"client" (which failed), causing the redirect to login.

The fix was equally simple: Change the sidebar include to match the
user's actual role.
